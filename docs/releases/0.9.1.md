# Wave Race 64: Recompiled 0.9.1

The riders hold together between frames, the two-player race start no longer
flickers, the course-edge buoys no longer slide, and **Draw Distance is no longer
experimental** -- it is rebuilt around the one number the game actually uses, and
it extends the sea out to the horizon.

**You need your own dump of Wave Race 64 (USA) (Rev A), also called v1.1**
(revision 1, header CRC `0x492F4B61 0x04E5146A`). No other version works. The
launcher checks the file you pick.

## Download

| | |
|---|---|
| **Windows x64** | `WaveRace64Recomp-0.9.1-windows-x64.zip` — unzip, run `WaveRace64Recomp.exe`, pick your dump. Debug symbols are in `…-debug-symbols.zip`, needed only for a readable crash report. |
| **Linux x86-64** | `WaveRace64Recomp-0.9.1-linux-x86_64.tar.gz` — extract, run `./WaveRace64Recomp.sh`. The libraries it needs come from your distribution; `README-LINUX.txt` inside lists them per distro. |
| **macOS (Apple Silicon)** | **No binary in this release.** It builds — `bash tools/setup_macos.sh` then `bash tools/build_macos.sh <your dump>` — but nobody here has a Mac to build or sign one on. |

Settings, saves and mods from 0.9.0 carry over, with one exception: **Draw
Distance** is now a distance rather than a multiplier, so a value saved by 0.9.0
comes back as **Original** rather than being misread. Set it again once. They
live in `%LOCALAPPDATA%\WaveRace64Recomp` on Windows,
`$XDG_DATA_HOME/WaveRace64Recomp` (or `~/.local/share/…`) on Linux and
`~/Library/Application Support/WaveRace64Recomp` on macOS. The log to attach to a
bug report, `wr64.log`, is in the same folder.

Each archive contains the recompiled game code and none of the game's assets;
the executable is a GPL-3.0 combined work (see the README's *Licensing*), and its
source is this repository at tag `v0.9.1`.

## What changed

### Interpolation

The game updates at 20 or 30 frames a second and RT64 draws the frames between,
by pairing what one frame draws with the previous frame's and moving it between
the two. Three things were being paired wrongly.

- **Riders hold together.** In a race, a part of a rider -- an arm, a leg, a piece
  of the craft -- jumped ahead of the body every few frames, and on the
  watercraft select screen parts jumped whenever the selection changed. RT64 was
  pairing a rider's parts by guesswork: mirrored parts look alike to it, so a
  part's previous pose was taken by its twin, and the part left over was drawn
  apart from the body, then snapped again. Every part is now paired with itself
  and always moves with the rest; a model that gains parts on a switch takes its
  new pose in one piece. Over two minutes of racing, 79,362 part pairs and none
  snapped.
- **The two-player race start no longer flickers.** For over a second after a
  2P VS race fades in, each view flickered between two shots: RT64 was drawing
  each view through the *other* view's camera on the frames it generates. A
  camera now only continues a camera that draws into the same part of the screen.
- **The purple course-edge buoys no longer slide.** As the game reshuffles its
  list of buoys, RT64 paired each with a neighbour hundreds of units along the
  row and slid it there -- plainest in the opening sequence at maximum draw
  distance. A pairing further apart than anything in this game can move between
  two frames is now refused.

All three were measured before and after and confirmed on screen; none costs
frame rate. [TRANSFORM-PAIRING.md](../TRANSFORM-PAIRING.md) is the write-up, with
the tools that found them.

### Draw Distance, rebuilt

- **No longer experimental.** It was a multiplier over per-object limits. A census
  of every draw over 5,000 race frames on two courses found there is one number per
  course deciding how much of it is drawn, and 49 of the 57 kinds of fixed scenery
  measured -- buoys, gate markers, the shoreline, the props -- move out with it.
- **A distance, not a multiplier**: Original, Far (8,000), Very far (12,000) and
  Maximum (16,192), the far plane. The game's own value is 2,500 to 6,000
  depending on the course, so a multiplier meant something different on each.
  The furthest object measured on any course sits at 13,175. Original still writes
  nothing to the game's memory.
- **A bug that silently switched it off on some courses** is fixed: moving between
  a 2,500 course and a 5,000 course left the port believing its work was done.

The course's direction arrows are not reached by it -- they are chosen by where you
are, not culled by distance.

### The sea reaches the horizon

The game animates a patch of water 922 units across and paints everything beyond
it onto the sky, which is why the water seemed to stop almost at your feet. The
port now draws the missing surface, as soon as **Water** or **Draw Distance** is
set above Original, out to the course's own limit or the Draw Distance setting,
whichever is further. Its heights come from the same wave field the game's own
waves stand on, and it uses the game's own texture and translucency, so it works
with the water renderer on or at Original and the swell outside agrees with the
swell inside. With both at Original the frame is exactly the game's.
`WR64_NO_WATER_RING=1` switches it off.

Measured on an Intel Iris Xe laptop over five configurations of the attract demo:
the game's own 20 frames a second held in 98% of two-second windows with and
without the sea and the raised distance, and 96% with High water, the sea and
Maximum distance at once.

### For people working on the port

- **`tools/capture_frames.py`** records every frame the game's window shows, even
  with another window on top of it; **`tools/contact_sheet.py`** tiles them.
- **A pairing log** (`WR64_PAIRING_LOG`, read with `tools/pairing_log.py`) records
  every camera and object pairing RT64 makes.
- **Input scripts** for a two-player race (`2:` in a script is player two, no
  second pad needed) and for switching riders on the select screen.
- **`tools/render_distance_census.py`** and
  [RENDER-DISTANCE-CENSUS.md](../RENDER-DISTANCE-CENSUS.md): which scenery the
  game stops drawing at a distance, measured rather than assumed.

## Known issues

- **macOS is untested by this project** -- Elliott Tate's work, kept compiling
  here. Treat a macOS-only failure as a real bug and report it.
- **The two-player fix was checked on one course**, Sunny Beach. The mechanism is
  not course-specific, but other courses have not been watched.
- **The water renderer has not been run on a Vulkan GPU.** The Linux build was
  exercised on Mesa's software rasteriser, because WSL exposes no GPU.
- **One kind of scenery on Sunset Bay** is drawn to about 5,100 units whatever
  Draw Distance says; its own limit has not been found.
