# Wave Race 64: Recompiled 0.7.0

The mods release. The **Mods** tab installs, enables and reorders mods, and this
port adds **texture packs** — read straight out of the mod file, applied in the
order the tab shows, and switchable without restarting the game.

**You need your own dump of Wave Race 64 (USA) (Rev A), also called v1.1**
(revision 1, header CRC `0x492F4B61 0x04E5146A`). No other version works. The
launcher checks the file you pick.

## Download

`WaveRace64Recomp-0.7.0-windows-x64.zip`: unzip anywhere, run
`WaveRace64Recomp.exe`, pick your dump. Settings, saves and mods go to
`%LOCALAPPDATA%\WaveRace64Recomp`, and so does `wr64.log`, the file to attach to
a bug report. Settings from earlier versions carry over.
`WaveRace64Recomp-0.7.0-windows-x64-debug-symbols.zip` is not a second build: it
holds the debug symbols for the same executable, only needed for a readable crash
report.

The zip contains the recompiled game code and none of the game's assets; the
executable is a GPL-3.0 combined work (see the README's *Licensing*), and its
source is this repository at tag `v0.7.0`.

## Mods

A mod is a `.nrm` — a zip with a `mod.json` at its root — installed from the Mods
tab or dropped into `%LOCALAPPDATA%\WaveRace64Recomp\mods`.

| Content | Declared by | Handled by |
|---|---|---|
| **Texture pack** | `rt64.json` | this port, through RT64's replacement system |
| Recompiled code | `mod_binary.bin` + `mod_syms.bin` | the runtime, recompiled live at load |
| ROM patch | `patch.bps` | the runtime |

A mod is detected as carrying a kind of content simply by containing the file
that declares it; nothing in `mod.json` says which it is.

**The runtime half of this had been running since 0.1.0.** `recomp::start` calls
`initialize_mods()` and `scan_mods()` on its own, the port had always given
librecomp this game's mod id, and the `mods` and `mod_config` folders have been
in the settings directory the whole time. What was missing was any way to see
what was in them — so a mod could have been installed and never appeared, never
been enabled, and never reported why it failed to open. Two calls fixed that.

**Texture packs** are this port's own addition. RT64 has a complete
replacement-texture system and reads a pack straight out of a zip without
unpacking it, so the `.nrm` *is* the pack — nothing is written to disk. What RT64
could not do was be *told* which packs to load by the program embedding it; its
only entry point is a file dialog in its developer UI.
`tools/patch_rt64_texturepacks.py` adds one function for that, applied on the
next frame because a mod can be switched on from another thread while the game is
running and loading a pack rebuilds the texture cache.

`tools/pack_mod.py` builds a `.nrm` from a directory and can drop it straight
into the mods folder. [examples/mods/](../../examples/mods) has a working
template and the workflow, including how to get texture hashes out of the game
with **F1 → Textures → Start dumping textures** — and the part that matters for
this project: ship your own images, never the game's textures or anything derived
from them by upscaling.

## Also new

**Field of View** in the Graphics tab, 45 to 110 degrees. The game draws at 45;
higher shows more of the world without stretching anything, because the
horizontal half of the frustum is derived from the vertical one and the aspect
ratio. The ratio is applied to every perspective pass of the frame, not just the
first — the sky has a frustum of its own and comes apart from the world otherwise
— and menus are excluded, because they lay their 2D out under a perspective
projection too. At 45 no matrix is rewritten at all, so the default costs
nothing.

## What is not here

**No draw distance setting**, because there is nothing for one to reach. The
race world's frustum was measured at near 10, far 16191.8 — about twenty times
further out than anything the game draws. Quartering the far plane changes
nothing on screen; only at a twentieth does the scene begin to clip, and then the
sky, the pier and the far islands all vanish at once. What limits the view is the
geometry the game builds — the water lattice is carried around the camera and the
courses are not large — which is decided in the game's code, not in the display
list. The numbers are in [GAME-INTERNALS.md](../GAME-INTERNALS.md), *The world's
frustum*, and the test that settles the question for another port is in
[PORTING.md](../PORTING.md).

The wipe between the rider-select and course-overview screens is still boxed in
the middle 4:3, as in 0.6.0.

## Known issues

- The wipe between the select screens stays 4:3.
- In a 4:3 window the picture is letterboxed; fullscreen on a widescreen display
  has no bars.
- The results screen's layout is wrong when HUD Placement is larger than
  Original, and the MAX POWER banner loses its last letter while the HUD layout
  is on.
- No announcer volume.
- Windows only, for now.
