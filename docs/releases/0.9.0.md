# Wave Race 64: Recompiled 0.9.0

The port runs on **Linux and macOS** as well as Windows, and there is a **modern
water renderer**. Both come from [Elliott Tate](https://github.com/elliotttate)'s
[pull request #2](https://github.com/danielgomesvieira2000/wave-race-64-recomp/pull/2)
— see [Credits](#credits).

**You need your own dump of Wave Race 64 (USA) (Rev A), also called v1.1**
(revision 1, header CRC `0x492F4B61 0x04E5146A`). No other version works. The
launcher checks the file you pick.

## Download

| | |
|---|---|
| **Windows x64** | `WaveRace64Recomp-0.9.0-windows-x64.zip` — unzip, run `WaveRace64Recomp.exe`, pick your dump. Debug symbols are in `…-debug-symbols.zip`, needed only for a readable crash report. |
| **Linux x86-64** | `WaveRace64Recomp-0.9.0-linux-x86_64.tar.gz` — extract, run `./WaveRace64Recomp.sh`. The libraries it needs come from your distribution; `README-LINUX.txt` inside lists them per distro. |
| **macOS (Apple Silicon)** | **No binary in this release.** It builds — see below — but nobody here has a Mac to build or sign one on. `bash tools/setup_macos.sh` then `bash tools/build_macos.sh <your dump>` produces a double-clickable, ad-hoc signed `.app`. |

Settings, saves and mods from 0.8.1 carry over unchanged. They live in
`%LOCALAPPDATA%\WaveRace64Recomp` on Windows,
`$XDG_DATA_HOME/WaveRace64Recomp` (or `~/.local/share/…`) on Linux and
`~/Library/Application Support/WaveRace64Recomp` on macOS. The log to attach to
a bug report, `wr64.log`, is in the same folder.

Each archive contains the recompiled game code and none of the game's assets;
the executable is a GPL-3.0 combined work (see the README's *Licensing*), and
its source is this repository at tag `v0.9.0`.

## What was added

### Linux and macOS

- **A Linux build**, verified on Ubuntu 26.04 with Clang 21: builds, runs, boots
  the game, walks the menus and races.
- **A macOS build** for Apple Silicon, producing an application bundle with its
  dylibs bundled, its install names rewritten and an ad-hoc signature.
- **Two commands from a clean clone** on either: `tools/setup_linux.sh --install`
  or `tools/setup_macos.sh`, then `tools/build_linux.sh` / `tools/build_macos.sh`
  with your dump. They install or report the packages, fetch the reference
  decompilation, build the Python environment splat needs, apply every submodule
  patch, build the recompiler, generate the game sources and compile.
- **Per-platform settings locations**, following each platform's own convention
  rather than one path with the separators changed.
- **Release packaging for both**: `tools/package_release.py` writes a `.tar.gz`
  on Linux and a `.zip` of the signed bundle on macOS, beside the existing
  Windows `package_release.ps1`. Neither will package a dump or a save, and
  neither overwrites an archive that already exists.
- **`tools/build_macos_dependencies.sh`** builds SDL2, FreeType and libpng from
  checksum-pinned source against the bundle's deployment target, so a published
  `.app` does not demand a newer macOS than it claims to support.
- The `tools/` scripts no longer assume a checkout path or a WSL host: they
  derive the repository root from their own location and find MIPS binutils
  natively where it exists.

### The modern water renderer

All of it is Elliott Tate's work. It keeps the cartridge's waves, physics and
timing exactly as they are and changes only how that surface is shaded, so the
craft handles identically at every setting.

- **A Water tab**, beside Graphics, with every water setting in it.
- **Water: Original, Modern or High.** Modern adds sun and sky lighting, colour
  that deepens with the water, refraction, wakes that persist behind each craft
  and wash along the shoreline. High adds reflections of the scenery in view and
  fine airborne spray. **High with the Aqua style is the default.**
- **Water style: Classic, Modern or Aqua** — least to most departure from the
  cartridge. Classic keeps the game's own colours, transparency, fog and broad
  highlights and adds only the effects.
- **Water brightness, Aqua tint and Water clarity**, for the Aqua style.
- **Surface ripples** (Soft / Normal / Strong) and **Spray particles** (on/off).
- **Ten per-course profiles**, in `assets/water/profiles.json`, validated on
  load with a compiled fallback.
- **F9** compares against Original from the same camera; **F10** cycles the
  renderer's diagnostic views.
- **Original is a true bypass**, not a degraded mode: the renderer is not
  engaged at all and the water is exactly the cartridge's.

**It costs what it looks like it costs.** On an M3 Max, Modern adds about
0.6 ms and High about 1.1 ms to the median game-rendering GPU time at 1080p.
Measured against the Original path at 0.97 ms, that is roughly double. If your
machine is comfortably ahead of the game's frame rate you will not notice; if it
is only just keeping up, you will. Step down to Modern, or to Original.

### Smaller things

- **`--version` prints the actual version.** It had said 0.4.0 since 0.4.0; the
  version now comes from the one place it is declared.
- **Three more 2D elements** placed correctly — the three that were being forced
  to *spill* now use the default centred placement, bringing the port's built-in
  table to 41 entries.
- **An intermittent crash on exit is fixed**: the runtime was releasing its
  thread queues and RDRAM without waiting for the workers still reading them.
- **Two new reference documents**: [WATER.md](../WATER.md) for what the settings
  do and how to build something like it elsewhere, and
  [WATER-IMPLEMENTATION.md](../WATER-IMPLEMENTATION.md), which describes the
  fork's implementation in full and states exactly what differs here.

## One settings note

The water quality setting moved from the Graphics tab into the Water tab during
development, and an option's id decides which file stores it. If you ran a
development build that wrote `water_quality` into `graphics.json`, that value is
not carried over: the Water tab's default applies once, and from then on
`water.json` is authoritative. Nothing else is affected, and 0.8.1 settings are
untouched by this.

## Known issues

- **macOS is untested by this project.** It is Elliott Tate's work, built and
  played by him on an Apple M3 Max, and kept compiling here. Nobody here has a
  Mac. Treat a macOS-only failure as a real bug and report it.
- **No GPU frame-cost measurement for the water outside macOS.** The Apple
  figures above are the only real before/after. On the Intel Iris Xe used here
  the game held its own rate at Original, Modern and High alike, which says the
  headroom was not exhausted, not that the settings cost the same.
- **The water renderer has not been run on Vulkan.** It compiles for it. The
  Linux build was exercised with water at Original, on Mesa's software
  rasteriser, because WSL exposes no GPU.
- **Split screen has not been tried with the water renderer** here; the fork
  measured it.
- **Draw Distance is still experimental** — unchanged from 0.8.1. Anything above
  Original makes the buoys flicker and slide as they come into view.

## Credits

**[Elliott Tate](https://github.com/elliotttate)** wrote the modern water
renderer and the native macOS support, and offered both to this project in
[pull request #2](https://github.com/danielgomesvieira2000/wave-race-64-recomp/pull/2).
The renderer is his: the RT64 passes, the interpolation that survives the game
recentering its water lattice, the depth handling, the wake and foam fields, the
shoreline intersection, the spray, the course profiles and the shaders. He also
identified the race-state addresses this port's rumble is built on.

This repository moved the renderer onto its own display-list rewriter, delivered
it as an idempotent patch script, fixed two faults that only appear away from
macOS — the material never reaching the renderer, and a missing precondition
that crashed the graphics thread — and documented it.
[WATER-IMPLEMENTATION.md](../WATER-IMPLEMENTATION.md) separates what he built
from what changed here, so neither is credited to the wrong party.
