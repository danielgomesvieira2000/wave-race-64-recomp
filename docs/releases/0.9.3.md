# Wave Race 64: Recompiled 0.9.3

Every buoy, all the way out. Draw Distance is now simply **Original** or
**Extended**, and at Extended every buoy in view is drawn -- no more buoys
popping in at a distance, and no more purple edge buoys glitching and vanishing
near the end of a lap -- on both screens of a two-player race.

**You need your own dump of Wave Race 64 (USA) (Rev A), also called v1.1**
(revision 1, header CRC `0x492F4B61 0x04E5146A`). No other version works. The
launcher checks the file you pick.

## Download

| | |
|---|---|
| **Windows x64** | `WaveRace64Recomp-0.9.3-windows-x64.zip` — unzip, run `WaveRace64Recomp.exe`, pick your dump. Debug symbols are in `…-debug-symbols.zip`, needed only for a readable crash report. |
| **Linux x86-64** | `WaveRace64Recomp-0.9.3-linux-x86_64.tar.gz` — extract, run `./WaveRace64Recomp.sh`. The libraries it needs come from your distribution; `README-LINUX.txt` inside lists them per distro. |
| **macOS (Apple Silicon)** | **No binary in this release.** It builds — `bash tools/setup_macos.sh` then `bash tools/build_macos.sh <your dump>` — but nobody here has a Mac to build or sign one on. |

Settings, saves and mods from 0.9.2 carry over. **Draw Distance saved as Far,
Very far or Maximum comes back as Extended**; Original stays Original. They live
in `%LOCALAPPDATA%\WaveRace64Recomp` on Windows, `$XDG_DATA_HOME/WaveRace64Recomp`
(or `~/.local/share/…`) on Linux and `~/Library/Application Support/WaveRace64Recomp`
on macOS. The log to attach to a bug report, `wr64.log`, is in the same folder.

Each archive contains the recompiled game code and none of the game's assets;
the executable is a GPL-3.0 combined work (see the README's *Licensing*), and its
source is this repository at tag `v0.9.3`.

## What changed

### Draw Distance: Original or Extended

| | |
|---|---|
| **Original** | The game's own: the course drawn to between 2,500 and 6,000 units depending on the course. Nothing is written to the game's memory. |
| **Extended** | The whole course to the far plane, every buoy in view, and the sea out to the horizon. What Maximum was, plus everything below. |

The steps in between did nothing Extended does not do better: the furthest object
on any course sits well inside the far plane, so there was only ever one distance
worth having above the game's own.

### Every buoy in view is drawn

The game only has room for **32 small buoys and 12 racing buoys** on screen at a
time, and it hands those places out in the order the course lists its buoys, not
by distance. At the game's own draw distance that is rarely a problem. At a raised
one it is everywhere: up to 120 buoys can be in view, so buoys as close as 2,000
units were left out -- and the ones left out were drawn using a place from an
earlier frame, on top of another buoy or where they used to be.

- **Distant buoys popped in** as nearer ones left the view and freed a place.
- **The purple edge buoys glitched and vanished near the end of a lap.** There
  the end of the edge row, its start past the line and the course's first buoys
  are all in view at once, and the nearest come last in the list.

At Extended the port now keeps those buoys in memory of its own, one fixed place
per buoy, with no limit, and widens the area the game checks for buoys to match
the Field of View setting. Measured over a race: **10,455 buoys left out became
none**, using the same share of the frame's drawing budget, which still has more
than 40% to spare. At Original the game's own behaviour is untouched.

### Extended works on both screens in two-player

Each player's view has its own copy of the course's draw distance, and only the
second player's was being raised: in a two-player race, player one kept the
game's own distance. Both are raised now.

### For people building from source

- The buoy fix lives in the generated game code, through hooks in
  `recomp/wr64.toml`. **Regenerate the game sources** after updating --
  `python tools/generate_game.py <your dump>` -- or the port builds without it.
- `WR64_BUOY_TRACE=1` reports how many buoys were in view, how many were drawn,
  and how full the frame's display list got; `WR64_BUOY_ORIGINAL=1` restores
  the game's buoy behaviour for comparison.
- [GAME-INTERNALS.md](../GAME-INTERNALS.md) now documents both buoy tables, their
  slot limits and the per-view course environment;
  [PORTING.md](../PORTING.md) covers moving a full game buffer into unused memory
  with recompiler hooks, and regenerating correctly.

## Known issues

- **macOS is untested by this project** -- Elliott Tate's work, kept compiling
  here. Treat a macOS-only failure as a real bug and report it.
- **The water renderer has not been run on a Vulkan GPU.** The Linux build was
  exercised on Mesa's software rasteriser, because WSL exposes no GPU.
- **Buoy drawing was measured on two courses** in one- and two-player races. If
  a course ever has more buoys in view than the frame's display list can hold,
  the furthest are left out rather than overflowing it; none were.
- **One kind of scenery on Sunset Bay** is drawn to about 5,100 units whatever
  Draw Distance says; its own limit has not been found.
