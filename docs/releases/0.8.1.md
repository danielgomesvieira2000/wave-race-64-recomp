# Wave Race 64: Recompiled 0.8.1

A small release on top of [0.8.0](0.8.0.md): eleven more 2D elements placed
correctly, and **Draw Distance marked experimental**, because it has a fault
worth warning about rather than leaving for players to find.

**You need your own dump of Wave Race 64 (USA) (Rev A), also called v1.1**
(revision 1, header CRC `0x492F4B61 0x04E5146A`). No other version works. The
launcher checks the file you pick.

## Download

`WaveRace64Recomp-0.8.1-windows-x64.zip`: unzip anywhere, run
`WaveRace64Recomp.exe`, pick your dump. Settings, saves and mods go to
`%LOCALAPPDATA%\WaveRace64Recomp`, and so does `wr64.log`, the file to attach to
a bug report. Settings, mods and saves from 0.8.0 carry over unchanged.
`WaveRace64Recomp-0.8.1-windows-x64-debug-symbols.zip` holds the debug symbols
for the same executable, only needed for a readable crash report.

The zip contains the recompiled game code and none of the game's assets; the
executable is a GPL-3.0 combined work (see the README's *Licensing*), and its
source is this repository at tag `v0.8.1`.

## Draw Distance is experimental

Anything above **Original** makes the buoys **flicker and slide** as they come
into view. They pop in cleanly out of the fog at Original, so this is something
the setting introduces rather than something it reveals.

What is known so far:

- It happens at **every** setting above Original -- 1.5x behaves no better than
  4x -- so it is not a matter of distance or of precision at range, both of which
  would get worse the further out you looked.
- The two symptoms are one fault. RT64 draws the frames between the game's by
  pairing each object's transform with the previous frame's; a buoy that keeps
  appearing and disappearing either finds no pair or finds the wrong one, and
  then slides in from wherever that other transform was. Fix the flicker and the
  sliding goes with it.
- The limit was being written from the graphics thread while the game read it on
  its own. **That is fixed here** -- it is now written once per frame, on the
  thread that reads it, at the point the port already uses for the Music Volume
  setting -- and it was not the cause. The flicker survives it.

The likeliest remaining explanation is that the game caps how many buoys it will
draw, so raising the distance gives it more candidates than it has room for and
it cycles which ones it picks. That would explain why the fault appears the
instant the limit is raised at all. It has not been confirmed, and
`WR64_DRAW_DISTANCE_TRACE=1` now records the limit every frame so the next look
starts from data rather than from a theory.

**Original is completely unaffected**: at that setting nothing is written to the
game's memory at all. The setting keeps its 4x range for anyone who prefers the
extra reach to the flicker, and now says what it costs.

## Eleven more 2D elements

Found with the debug menu on **F1** and tagged into the port's built-in table,
where they reach every player rather than only the machine that found them. That
brings the table to **forty-three entries**.

Eight are elements that should stay put and were being moved, and three more are
`spill` -- the class added in 0.8.0 for something that is in the right place at
the right size and was merely being cut off at the old frame's edge. Two of the
eleven reverse earlier decisions, which is what the inspector is for: a judgement
made from one frame is worth revising when a later one disagrees.

## Known issues

Unchanged from [0.8.0](0.8.0.md), with Draw Distance's flicker added above:

- The **MAX POWER banner** loses its last letter when the HUD layout is on. The
  letter is clipped by the coordinates the game gives its own rectangle rather
  than by the frame, so none of the 2D classes reach it.
- In a 4:3 window the picture is letterboxed -- the overscan borders a CRT hid.
  Fullscreen on a widescreen display, the default, has none.
- There is **no separate volume for the announcer**.
- Windows is what this project builds and tests today.
