# Wave Race 64: Recompiled 0.8.0

The release that fixes what you hear and the port's oldest known fault. Audio is
clean, the transition wipe covers the frame, closing the game no longer crashes
it, and **Draw Distance** stops the buoys appearing out of nothing.

**You need your own dump of Wave Race 64 (USA) (Rev A), also called v1.1**
(revision 1, header CRC `0x492F4B61 0x04E5146A`). No other version works. The
launcher checks the file you pick.

## Download

`WaveRace64Recomp-0.8.0-windows-x64.zip`: unzip anywhere, run
`WaveRace64Recomp.exe`, pick your dump. Settings, saves and mods go to
`%LOCALAPPDATA%\WaveRace64Recomp`, and so does `wr64.log`, the file to attach to
a bug report. Settings, mods and saves from 0.7.x carry over unchanged.
`WaveRace64Recomp-0.8.0-windows-x64-debug-symbols.zip` holds the debug symbols
for the same executable, only needed for a readable crash report.

The zip contains the recompiled game code and none of the game's assets; the
executable is a GPL-3.0 combined work (see the README's *Licensing*), and its
source is this repository at tag `v0.8.0`.

## The audio is clean

Two separate faults, each measured rather than guessed at, and both fixed.

**A crackle in everything.** SDL's queued-audio drain asks for a whole device
period every time the sound card pulls, takes whatever is in the queue, and fills
the rest with silence without waiting. The queue was running at less than half a
period and touching **empty in every one of the forty-five two-second windows of
a ninety-second run** -- about nineteen frames short each period, which is a
0.7 ms hole in the sound twenty-six times a second, continuously. The port now
keeps 30 ms in hand and asks the device for 256 frames at a time. The samples
themselves were never at fault: a dump of the same run plays back clean.

**A fizz on anything bright.** The game asks for 26900 Hz in a race and 32000 in
the menus, and no sound card runs either, so something resamples. SDL was, and it
loses continuity at every boundary of the block it is fed:

| 26900 -> 48000 Hz, 8 kHz tone | signal to everything else |
|---|---|
| SDL, fed in 448-frame blocks | **14.4 dB** |
| SDL, fed in one single call | 43.4 dB |
| this release | **91.0 dB** |

The middle row is what proves it was the block boundaries rather than the filter:
one converter, one ratio, one signal. The port now converts the rate itself, with
filter state carried across buffers so there are no boundaries at all -- measured
identical whether fed 64 frames at a time or 4096 -- and opens the device at the
rate the machine actually runs. About 1.5% of one core.

Two things fall out of that. The pitch stops drifting: SDL's converter rounds to
a whole number of output frames per call and shifted 26900 -> 48000 by +0.07 %.
And the device is never reopened when the game changes rate, so the gap in the
sound at every entry to and exit from a race is gone with it.

## The transition wipe covers the frame

Open since 0.3.0 and the port's oldest known issue: the wipe between the select
screens stayed boxed in the middle 4:3 while every rectangle around it was placed
correctly.

RT64 already renders a pass that covers the frame across the widened frame. What
stopped this one was the viewport origin this port sets on a menu's perspective
pass, to keep 3D objects inside the boxes a 2D layout gives them -- right for the
watercraft on the rider-select screen, wrong for a curtain meant to cover the
screen. The origin now comes off for that one call and goes back after. Nothing
is stretched and no projection is rewritten.

Telling the curtain from the watercraft is the part that took the work: they use
the **same** projection, and the viewport that distinguishes them is loaded
*inside* the display list the curtain is drawn from, where the rewriter -- which
emits a call and lets RT64 walk in -- cannot see it. The write-up in
[PORTING.md](../PORTING.md) has the whole of it, including two traps worth
knowing for any port that rewrites display lists.

## Closing the game no longer crashes it

It had been dying with an access violation on every normal exit, after everything
had reported itself shut down. RT64 chains itself into SDL's event filter and
never takes itself back off, so SDL still held a pointer to the destroyed object
and the messages `SDL_DestroyWindow` pumps made a virtual call through freed
memory. `tools/patch_rt64_eventfilter.py` supplies the missing half.

## Draw Distance

In the Graphics tab, up to 4x. There is no global draw distance in this game --
the far plane is already twenty times further out than anything drawn, and each
kind of object is culled by its own code -- so this is one setting over the limits
that have been found. Today it reaches the buoys, which the game drops **between
2500 and 5000 units depending on the course** while drawing the world to 16,192.
At 4x on a 2500 course the count drawn goes from a handful to the whole course.

The per-course variation is worth knowing: 2x on a 2500 course only gets you what
a 5000 course has by default.

## Also

**The sun over a race reaches past the old frame's edge.** It is drawn as a 48x48
square running deliberately off the left of the game's own screen, and on a
widened frame it stopped dead at the 4:3 boundary. A fifth 2D class, `spill`,
lifts the 4:3 scissor for an element that is already in the right place at the
right size and is merely being cut -- the only one of the five about clipping
rather than placement. Its disc, glare and haze ship tagged, bringing the port's
built-in table to thirty-three entries.

**For anyone working on a port of their own**, `docs/PORTING.md` gains the audio
queue arithmetic, the resampler measurements, the SDL event-filter lifetime trap,
a way to recover a stack from a crash with no unwind data, and the curtain. The
diagnostics behind them ship in the build: `WR64_AUDIO_STATS`, `WR64_AUDIO_DUMP`,
`WR64_3D_TRACE_EVERY` and `WR64_NO_CURTAIN`.

## Known issues

- The **MAX POWER banner** loses its last letter when the HUD layout is on. The
  letter is clipped by the coordinates the game gives its own rectangle rather
  than by the frame, so none of the 2D classes reach it; it needs the rectangle
  widened, which the rewriter cannot do yet.
- In a 4:3 window the picture is letterboxed. The game draws a 303x199 region of
  its 320x240 framebuffer -- the overscan borders a CRT hid -- and fullscreen on
  a widescreen display, the default, has no bars.
- There is **no separate volume for the announcer**; it is not separable the way
  music and effects are. See [PORTING.md](../PORTING.md).
- Windows is what this project builds and tests today. A fork carries native
  macOS support; wider platform coverage is intended. Nothing in this release's
  audio work is Windows-specific -- the resampler is plain C++ and the SDL bug it
  works around is in SDL's cross-platform code.
