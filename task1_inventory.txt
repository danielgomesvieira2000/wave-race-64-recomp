## Arquitetura de 3 Fases (ELF -> Recompilation -> CMake)

### Fase 01: ELF Generation
```
Input: Wave Race 64 (USA) Rev A .z64 ROM
Toolchain: splat + mips binutils
Process:
  - Disassembly via splat into /asm/
  - Assembly back into wr64.elf with symbols
  - Symbol recovery from reference decomp (804 func_XXXX symbols)
  - JAL scan for unresolved call targets (tools/jal_scan.py)
  - Byte-identical verification against ROM code sections
Output: wr64.elf (not committed, gitignored)
```

### Fase 02: Recompilation (N64Recomp)
```
Input: wr64.elf + recomp/wr64.toml
Tools: N64Recomp CLI, RSPRecomp for audio
Process:
  - ~1,350 functions compiled into C at 50 per file
  - 4 classes of fix applied (Phase 02 findings):
    1. Direct overlay calls -> use_lookup_for_all_function_calls
    2. Linker script override -> tools/fix_asmonly_ld.py
    3. Reimplemented funcs -> excluded from config
    4. Missing declarations -> tools/gen_reimplemented_decls.py
Output: RecompiledFuncs/ (not committed)
  - funcs_*.c (~27 files)
  - funcs.h
  - reimplemented_decls.h
  - runtime_funcs.inl
  - recomp_overlays.inl
  - aspMain_rsp.cpp
```

### Fase 03: CMake Build
```
Options phase-gated (docs/PLAN.md):
  WR64_WITH_RECOMPILED=ON     → compile RecompiledFuncs/*.c
  WR64_WITH_RUNTIME=ON        → link RT64 + ultramodern + librecomp
  WR64_BUILD_RECOMPILER=ON    → build N64Recomp from lib/
  WR64_WITH_FRONTEND=ON       → link RecompFrontend
  
Output: WaveRace64Recomp executable (Windows/Linux/macOS)
Compiler: Clang 15+ (GCC known to miscompile generated code)
```

## Patches Customizados

### 3 Types of Patches

1. **Replaces** (stubs/ignored in config)
   - Definições fortes vencem sobre weak symbols do código recompilado
   - Exemplo: `dma.cpp` substitui `game_dma_copy` por transferência síncrona
   - `game_dma_copy` marked `ignored` in wr64.toml → no generated code → no duplicate symbol

2. **Wrappers** (registered by address in src/overlays.cpp)
   - Envoltórios que enviam a chamada para o código original
   - Exemplo: `water.cpp` envolve func_8009345C e func_80046CF8 para renderização moderna
   - `framerate.cpp` envolve osViSwapBuffer para medição de framerate

3. **Hooks** (injected into generated C via TOML)
   - Pontos de inserção via address registers before_vram
   - 16 hooks on func_8006E674 for buoys system
   - Regenerates game sources when changed (tools/generate_game.py)

### Hook Configuration Example (wr64.toml)
```toml
[[patches.hook]]
func = "func_8006E674"
before_vram = 0x8006E6B8
text = "{ void wr64_buoys_begin(uint8_t* rdram, recomp_context* ctx); wr64_buoys_begin(rdram, ctx); }"
```

## Pontos Críticos para Reescrita C++

### 1. Dependência de ROM
- O código recompilado depende de um dump do jogo original (Wave Race 64 USA Rev A)
- Não há assets ou dados do jogo no repositório
- Símbolos derivados do ELF não são committed

### 2. Sistema de Overlays Complexo
- 19 seções compartilham VRAM 0x802C5800
- Overlay dispatch via runtime lookup (use_lookup_for_all_function_calls)
- 3 funções stubbed em phase 02 (func_80092CF0, func_800922E4, PauseMenu_Update)
- Overlay loads through osPiStartDma hook (patches/dma.cpp)

### 3. Áudio RSP
- Microcódigo de áudio recompilado via RSPRecomp (C++ output)
- Carrega em IMEM 0x04001080 (not 0x1000)
- 16 indirect branch targets para command handlers
- Output: RecompiledFuncs/aspMain_rsp.cpp

### 4. Display List Rewriter
- src/dlrewrite.cpp (3,423 lines) - sistema complexo de rewriter
- Handles widescreen, 2D HUD placement, aspect ratio
- Tracks segment table and matrix stack

### 5. Física e Sistema de Água
- func_8004D30C - Water height query (used by waterring, waterfield)
- Física do jet ski e água está no código recompilado (~1,350 funções)
- Sistema de água moderno em src/water*.cpp

## Viabilidade de Reescrita C++

### Pontos Positivos
1. Arquitetura modular bem definida via CMake phase-gating
2. Código fonte original em C++ moderno (C++20)
3. Separação clara entre core, patches e frontend
4. Sistema de hooks robusto para func_XXXX
5. Documentação extensa (GAME-INTERNALS.md, PORTING.md)
6. ~1,350 funções recompiladas são C gerado (reverse-engineerable)

### Desafios
1. ~1,350 funções recompiladas dependem de N64Recomp especificamente
2. Símbolos asm_only não podem ser reescritos sem análise completa
3. Padrão de chamadas baseado em endereços (use_lookup_for_all_function_calls)
4. Dependência de librecomp para overlay dispatch
5. RSP microcode precisa de RSPRecomp separado
6. Física do jogo não está decompilada (804 func_XXXX symbols, ~1,350 total)
7. GPL-3.0 dependencies limit C++ reimplementation options

### Recomendação
- **Reescrita completa:** Viável mas exige anos de engenharia reversa
  - ~1,350 functions need manual C++ reimplementation
  - Physics, audio RSP, and overlay dispatch all need reimplementing
- **Abordagem gradual (híbrida):** Mais viável
  - Manter N64Recomp output while progressively replacing func_XXXX
  - Use patches/ system for selective replacement
  - The CMake phase-gating supports incremental migration

### Conclusão Geral
O projeto tem uma base sólida para evolução, mas a reescrita completa requer:
1. Substituição de ~1,350 funções recompiladas por C++ nativo
2. Reimplementação do sistema de overlays (19 sections, shared VRAM)
3. Reimplementação da física do jogo (jet ski, water, collision)
4. Reimplementação do sistema de áudio RSP (microcode)
5. Reimplementação do display list rewriter (3,423 lines)
6. Extração de todos os assets do jogo original

A viabilidade é **moderada para reescrita completa** (requer anos de trabalho), mas **alta para abordagem incremental/híbrida** mantendo N64Recomp como base enquanto reescreve componentes específicos em C++ puro.
